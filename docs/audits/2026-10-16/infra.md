## 2. Versions, actions, caching, concurrency

**Go version drift (3 different values):**
- `backend/go.mod`: `go 1.24.0`
- `backend/Dockerfile`, `docker-compose.yml`: `golang:1.24-alpine`
- `checks.yml`: `go-version: '1.21'` (lower than go.mod — setup-go then relies on GOTOOLCHAIN auto-download), `Makefile GO_VERSION ?= 1.21`
- `deploy-release.yml`: `'1.24'`
- LL: `"1.26"` + `check-latest: true` everywhere (needed so govulncheck doesn't fail on stdlib CVEs fixed in newer patch). Recommend bump go.mod to `go 1.26` (or at least pin 1.24.x consistently) and `check-latest: true`.

**Node drift:** CI uses `node-version: '20'`, Dockerfile + compose use `node:22-alpine`, `Makefile NODE_VERSION ?= 20`. No `.nvmrc`, no `engines` in package.json. LL uses `"22"`. Pick 22, add `frontend/.nvmrc` (or `engines`), use `node-version-file`.

**Actions:** `checkout@v6`, `setup-go@v6`, `setup-node@v6`, `setup-python@v6`, `cache@v5` are current. Problems:
- `superfly/flyctl-actions/setup-flyctl@master` — unpinned branch ref (supply-chain risk); goes away with Fly.
- `cloudflare/pages-action@v1` — deprecated; replace with `cloudflare/wrangler-action@v3` (`command: deploy`).
- `softprops/action-gh-release@v2` — replaced by `gh release create` in `gh-release.sh`.
- golangci-lint installed via `curl .../master/install.sh` (unpinned script from master) — LL uses `golangci/golangci-lint-action@v9` with `version: v2.x`. ServicePro pins `GOLANGCI_LINT_VERSION ?= v2.1.6` (old; LL is v2.11.4).
- `goimports@latest` unpinned.

**Caching:** setup-go/setup-node caches are configured correctly (`cache-dependency-path`). pre-commit cache ok. No docker layer cache (no docker job exists). LL uses `type=gha,scope=api`.

**Concurrency:**
- `checks.yml`: `group: ci-${{ github.ref }}`, `cancel-in-progress: true` — cancels master runs too; LL only cancels PR runs (`${{ github.event_name == 'pull_request' }}`) so every tagged commit has a green run.
- `deploy-release.yml`: `group: deploy-release-${{ github.ref }}`, **`cancel-in-progress: true`** — dangerous: per-ref groups don't serialize two tags, and cancel could abort mid-deploy. LL: `group: release-production`, `cancel-in-progress: false`.

**Permissions:** `checks.yml` and `deploy-release.yml` have **no `permissions:` block** (inherit repo default, often write). LL sets `contents: read` in CI; `contents: write` + `id-token: write` in release; `{}` in cron jobs.

**Timeouts:** no `timeout-minutes` on any ServicePro job (default 360 min). LL: 10–25.

**Missing jobs vs LL ci.yml:**
- `go-vuln` (govulncheck) — missing
- `npm audit --audit-level=high` — missing
- `docker-build` + Trivy (`aquasecurity/trivy-action@0.35.0` — note the earlier tags were compromised) — missing
- `openapi-drift` — missing (and currently impossible as-is: `backend/docs/swagger.{json,yaml}`, `docs.go` and `frontend/src/types/api.generated.ts` are **gitignored**; swagger.json is 1.6 MB, docs.go 1.6 MB, yaml 1.0 MB). Decide: commit them (LL commits `api/docs`) and diff, or run `make docs` in CI and fail only if it errors/typecheck breaks. Recommend committing `backend/docs/swagger.json` + `swagger.yaml` + `docs.go` and `api.generated.ts`, matching LL, and drop the gitignore lines.
- DB-backed tests: ServicePro CI runs `go test ... -skip "Integration"`; `backend/tests/integration` exists but never runs in CI. LL runs go-test with a `postgres:16-alpine` service and a separate tagged integration job. Add a job with Postgres (+ Redis service, since the app needs it).
- `react-lint` as a separate job (today hidden inside pre-commit-in-CI).
- Workflow `workflow_dispatch` on CI (needed by dependabot-automerge).

**Secrets/vars used but undocumented anywhere:** `FLY_API_TOKEN`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, vars `VITE_API_URL`, `VITE_STRIPE_PUBLISHABLE_KEY`. `docs/deployment/README.md` is a "Coming Soon" stub. Frontend build also wants `VITE_SENTRY_DSN`, `VITE_POSTHOG_API_KEY/HOST` (see `frontend/.env.example`) which release never passes.

## 3. Dockerfiles and Cloud Run requirements

### backend/Dockerfile (current)
- `golang:1.24-alpine` builder; `go build ... -o main cmd//main.go` (double slash; works but sloppy). `-a -installsuffix cgo` is obsolete.
- **`COPY --from=builder /app/migrations ./migrations 2>/dev/null || true`** and same for `config` — this is **invalid Dockerfile syntax** (shell redirection is not allowed in COPY; BuildKit will treat `2>/dev/null`, `||`, `true` as source paths and fail). It has likely never been built in CI (no docker job). Must fix.
- Runtime `alpine:latest` (unpinned), runs as UID 1000 non-root (good), `WORKDIR /root/` chowned to appuser (odd).
- No `GIT_SHA` / `APP_VERSION` build args.
- HEALTHCHECK wget `/health` (fine for compose; Cloud Run ignores it).
- No `.dockerignore` in backend/ — `backend/main` (85 MB untracked binary), `backend/node_modules` (5 MB), `exports/`, `tests/` all get sent to the build context.

### frontend/Dockerfile + nginx.conf + security-headers.conf
Not needed for production on Workers. nginx currently provides: SPA fallback, `/api` proxy, CSP/HSTS/security headers, long cache on hashed assets, no-cache on HTML, `/health`. Map to Workers: SPA fallback = `not_found_handling = "single-page-application"`; `/api` proxy = Worker with `run_worker_first = ["/api/*", "/version"]`; headers = `frontend/public/_headers` (Workers static assets supports `_headers`) — note the CSP `connect-src 'self'` will need Sentry/PostHog/Stripe origins added; `/health` not needed. Also `npm ci --only=production=false` is a deprecated flag. Nothing in docker-compose uses this Dockerfile (compose runs `node:22-alpine` + `npm run dev`), so it can be deleted (or kept only if a containerized preview is wanted).

## 6. What LL does that does NOT apply (or needs rethinking)

- **Pages Functions** (`web/functions/**`, `pages deploy --branch=master` gotcha) — ServicePro uses a Workers static-assets Worker instead; the `--branch` detached-HEAD problem does not exist for `wrangler deploy`.
- **LL `web/wrangler.toml` `[site] bucket`** — legacy Workers Sites syntax, stale; don't copy.
- **Supabase Auth** pieces (`auth-up`, signing keys, `auth.users` backup dump, `SUPABASE_PUBLISHABLE_KEY` build env, `supabase/` dir) — ServicePro has its own JWT auth; only Supabase *Postgres* applies.
- **`tools/seed`** module, its dependabot entry and govulncheck step; `seed.yml`, `refresh-schedules.yml`; `sitemap`, `up-asof`, `generate-sitemap.mjs`; OG-image worker dependabot entry.
- **Affiliate secrets** (`LL_AFFILIATE_*`), `/go/*` partner redirect proxying.
- **LL-specific lifecycle jobs** (trip-countdown, season-kickoff, digest) — replace with ServicePro jobs (payment reminders, etc.).
- `docs/ops/ccpa-sop.md`, `slos.md`, `sentry-monitoring.md` — optional, not infra-blocking.
- `connection_string.txt` pattern in LL (an untracked credential file at repo root) — don't replicate.
